# 아키텍처 제약 및 설계 규칙 (Non-Obvious)

- **단일 코어 엔진 위임**: 8개 개별 서버 및 통합 서버는 모든 실제 동작을 `@ibm-docs-mcp/core`에 위임하며, 엔트리 파일은 3~5줄 수준의 실행 래퍼로만 유지됩니다.
- **라우팅 전략**: 통합 서버는 제품별로 개별 API 검색을 여러 번 호출(fan-out)하지 않고, 전체 컴포넌트 키를 대상으로 `limit: 40` 단일 검색을 수행한 후 메모리에서 제품별로 그룹화합니다 (요청 수 1/6 감소 및 재현율 100% 확보).
- **환경변수 기반 스코프 제한**: `IBM_DOCS_PRODUCTS=apic,idig` 환경변수로 서버 시작 시 노출할 제품을 필터링합니다. 대상 제품이 1개로 축소되면 스키마에서 `product` enum 파라미터가 완전히 제거됩니다.
- **TOC 단계별 탐색 전략**: 대규모 제품 문서는 전체 트리를 한 번에 펼치면 토큰/글자 수 제한을 초과합니다. `depth` 제어(기본값 1)와 `section` 필터를 단계적으로 활용하여 잘림 없이 탐색하도록 설계되어 있습니다.
